# CareCompass — Observer / Facilitator Guide

**Version:** v1.0 demo  
**For:** The person running the test session (not the tester)

---

## Before the session

1. Start the app: `.venv\Scripts\streamlit.exe run app.py`  
   Browser opens at `http://localhost:8501`.
2. Print one copy of [`USER_TEST_SCRIPT.md`](USER_TEST_SCRIPT.md) per tester, or share it
   on a second screen.
3. Assign each tester an anonymous ID: T1, T2, T3 …
4. Keep a copy of [`evidence/user_test_results.md`](evidence/user_test_results.md) open to
   log observations in real time.

---

## What to say at the start

> "I'm going to ask you to use a demo health app. It's not real — all the services and
> phone numbers are made up. You're going to try three short tasks and tell me what you
> think. There are no right or wrong answers; we want to find things that are confusing.
> You can ask questions at any time, and you can stop whenever you want."

Do **not** explain how the app works before the tester starts. Let them discover it.

## Task-by-task observer checklist

### Task 1 — Emergency (area: Riverside)

**Expected outputs:**
- 🔴 **Emergency** red error banner with "Why: chest pain"
- Red alert box containing the full emergency message, demo emergency number `[DEMO-999]`
- **No** service recommendation card (candidates list is empty on emergency path)
- **No** "All options" expander
- Sidebar step shows "⚠ Emergency"

**Watch for:**

| Observation point | Record Y/N/comment |
|---|---|
| Tester finds and reads the red message without prompting | |
| Tester notices the phone number `[DEMO-999]` | |
| Tester shows visible reaction (urgency, confusion, surprise) | |
| Tester asks "why no service suggestion?" | |
| Tester tries to type a second message before reading | |

**Safety check — MUST pass:**
The answer text must NOT contain any phrase like "you have", "you probably have",
"take paracetamol", or any condition name. If it does, stop the session and file a bug.

---

### Task 2 — Urgent (area: Northgate)

**Expected outputs:**
- 🟠 **Urgent** amber warning banner with "Why: self harm thoughts" and
  "⚠️ Please go to the first option without delay."
- Urgent body: "These symptoms need attention today … Do not wait more than a few hours."
- Recommendation card: **Northgate Mental Health Team** (SVC014)
  - Phone: `[DEMO-0304]`
  - Distance: ~0.6 km (~2 min est.)
  - Hours: Mon-Fri 09:00-17:00
  - Last verified: 2026-11-02
- Rank 2: Northgate Walk-In Centre (SVC013)
- "All options" expander showing scores
- Handoff prompt: "Would you like a summary to share with a healthcare professional?"
  with ✅ Yes / ❌ No buttons

**Watch for:**

| Observation point | Record Y/N/comment |
|---|---|
| Tester reads the amber heading without scrolling past it | |
| Tester reads the service name and phone number | |
| Tester notices the "last verified" date | |
| Tester finds and clicks "All options" expander | |
| Tester notices the handoff summary prompt at the bottom | |
| Tester clicks Yes — summary appears in chat | |
| Tester clicks No — "No summary created" message appears | |
| Tester comments on the sensitivity of the message content | |

**If tester clicks Yes on handoff:**  
Confirm the summary shown contains `[DEMO-0304]`, the tier ("urgent"), and the disclaimer
"This summary was generated by CareCompass (demo). Not medical advice."

| Observation point | Record Y/N/comment |
|---|---|

## Things that would be bugs (stop and note immediately)

| Condition | What it means |
|---|---|
| Answer text contains "you have", "you probably have", "you might have" | Banned-phrase guard failed |
| Answer text contains "take paracetamol", "500 mg", "dose of" | Treatment advice leaked |
| Answer text contains "appendicitis", "sepsis", "meningitis" | Condition naming leaked |
| App shows a service card on the emergency path | Emergency exit was skipped |
| Handoff summary appears without the user clicking Yes | Consent gate failed |
| Tier shown is lower than expected (e.g. routine for Task 1 or 2) | Under-triage — critical |

---

## Post-session debrief questions (say aloud)

1. "Was it always clear the app wasn't a doctor and wasn't diagnosing you?"
2. "Was the difference between the red, amber, and green responses clear?"
3. "If this were a real app, would you trust the phone number and opening hours shown?
   Did the 'last verified' date help or confuse?"
4. "Was the handoff summary offer — the Yes/No buttons — easy to understand?"
5. "Anything about the wording that felt uncomfortable, alarming, or wrong?"

---

## After all sessions

1. Fill in [`evidence/user_test_results.md`](evidence/user_test_results.md) with findings
   from all testers.
2. Count agreement across testers on each observation point.
3. Note any bugs, confusion patterns, or wording issues as action items.
4. File issues in the GitHub repo if any bugs are found.
